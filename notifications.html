Instant notifications

A guide for helpdesk administrators. Last updated 16 November 2026.

Clear Desk can tell an agent's iPhone or iPad about a new ticket, a customer reply, an assignment or a colleague's note within a few seconds. For this, the helpdesk's administrator installs a small free plugin on the osTicket server. This page explains every step.

Without the plugin there are no instant notifications. The rest of the app works the same with or without it.

What this is

  • The plugin is called Clear Desk notifications. The current version is 0.1.
  • It runs inside your osTicket. When something happens on a ticket, it works out which agents should be told and sends a short message, with no ticket content, to a delivery service. The delivery service passes it to Apple, and Apple shows it on the agent's device.
  • The plugin is free and open source, under the GPL v2 licence. You can read all of it before you install it: github.com/bartraigures/ClearDeskPlugin.
  • Notifications arrive in Clear Desk from version 1.1. They are part of the paid plan, Clear Desk Full. Each agent who wants them needs that plan. The plugin itself costs nothing.
  • A notification has the title "Ticket #374502" (with the ticket's number) and one of these texts: "New ticket", "The customer replied", "Assigned to you" or "A colleague added a note". Tapping it opens that ticket in the app.

What you need

  • A self-hosted osTicket, release 1.17 or 1.18. The plugin has been checked on 1.17, 1.18.2 and 1.18.4.
  • The hosted osTicket service (SupportSystem) cannot add plugins, so this does not work there.
  • PHP with the curl extension, on the server that runs osTicket.
  • The server must be able to make outbound HTTPS requests (port 443) to the delivery service at ng4e4cc4icqx5f45jn4ssql74e0jjcbn.lambda-url.eu-west-1.on.aws. A firewall that blocks outgoing connections must allow this one.
  • An osTicket administrator account.
  • A way to put files on the server: SFTP or FTP, your hosting company's file manager, or SSH.
  • For each agent: an iPhone or iPad with Clear Desk version 1.1 or later, and the Clear Desk Full plan.

Before you start

  1. Take a backup. The plugin runs inside your helpdesk, so back up the osTicket database and files first, as you would before any upgrade.

  2. Use a test copy if you can. If you have a test copy of your helpdesk, install the plugin there first and work through this guide on it. Then repeat the steps on the live helpdesk.

  3. Check your osTicket version. Sign in to the agent panel as an administrator, click Admin Panel, and look at the version shown on the Dashboard tab under Information. It must be 1.17 or 1.18.

  4. Check the server can reach the delivery service. If you have SSH access, run this on the osTicket server:

    curl -s https://ng4e4cc4icqx5f45jn4ssql74e0jjcbn.lambda-url.eu-west-1.on.aws/v1/health

    It should print exactly:

    {"ok":true}

    If it prints nothing, or an error, the server cannot reach the delivery service. Ask whoever manages the server or firewall to allow outbound HTTPS to that host. Without it the plugin cannot send anything. If you have no SSH access, ask your hosting company to run the check for you.

  5. Check PHP has the curl extension. By SSH, php -m lists the extensions; curl should be among them. The command-line PHP can differ from the one the web server uses, so if in doubt ask your hosting company. Most PHP installs include curl.

  6. Find osTicket's folder on the server. This is the folder that holds osTicket's own files, including the folders scp and include. In this guide it is written as /path/to/osticket.

    If you do not know where it is, sign in by SSH and run:

    sudo find / -name ost-config.php -not -path "/proc/*" 2>/dev/null

    It prints a line such as:

    /var/www/html/osticket/include/ost-config.php

    The folder you want is the part before /include. In that example it is /var/www/html/osticket.

    If it prints more than one line, the server holds more than one copy of osTicket (an old version or a backup, perhaps). Find out which one the website uses with whichever of these matches your web server:

    grep -R "DocumentRoot" /etc/apache2/sites-enabled/
grep -R "root " /etc/nginx/sites-enabled/

    Use the copy inside the folder that command names. Installing into the wrong copy does no harm, but the plugin will not appear in the admin panel.

    Inside include there is a folder called plugins. That is where the plugin goes. If there is no plugins folder inside include, create one.

Part 1: put the files on the server

At the end of this part, the plugin's files must be in a folder called cleardesk inside osTicket's include/plugins folder, like this:

/path/to/osticket/include/plugins/cleardesk/plugin.php
/path/to/osticket/include/plugins/cleardesk/config.php
/path/to/osticket/include/plugins/cleardesk/cleardesk.php

All three .php files are required. The folder name must be exactly cleardesk, in lower case. Choose one of the two routes below.

Route A: download the ZIP and upload it

  1. On your own computer, download the ZIP file: github.com/bartraigures/ClearDeskPlugin/archive/refs/heads/main.zip.

  2. Unzip it. You get a folder called ClearDeskPlugin-main. Inside it you should see five files: plugin.php, config.php, cleardesk.php, README.md and LICENSE.

  3. Rename the folder from ClearDeskPlugin-main to cleardesk.

    Check you have not ended up with a folder inside a folder. Opening cleardesk must show the five files straight away, not another folder.

  4. Connect to the server with your SFTP or FTP program, or open your hosting company's file manager. Go to /path/to/osticket/include/plugins.

  5. Upload the whole cleardesk folder into plugins.

    You should now see include/plugins/cleardesk on the server, and inside it plugin.php, config.php and cleardesk.php. README.md and LICENSE are not needed by osTicket but do no harm.

  6. Make sure the files can be read by the user the web server runs as. If your other osTicket files are readable by the web server, give the new folder and files the same owner and permissions.

Route B: by SSH, with git

  1. Sign in to the server by SSH.

  2. Go to osTicket's plugins folder:

    cd /path/to/osticket/include/plugins

  3. Download the plugin into a folder called cleardesk. The word cleardesk at the end of this command sets the folder name:

    git clone https://github.com/bartraigures/ClearDeskPlugin.git cleardesk

    If it answers "Permission denied", the folder belongs to another user. Run the same command with sudo in front:

    sudo git clone https://github.com/bartraigures/ClearDeskPlugin.git cleardesk

    If it answers that git is not found, download and unpack the ZIP on the server instead:

    sudo curl -L -o cleardesk.zip https://github.com/bartraigures/ClearDeskPlugin/archive/refs/heads/main.zip
sudo unzip cleardesk.zip
sudo mv ClearDeskPlugin-main cleardesk
sudo rm cleardesk.zip

  4. Check the files are there:

    ls -l . cleardesk

    This lists the plugins folder and then the new cleardesk folder. You should see something like:

    drwxr-sr-x 3 root www-data  4096 Nov 16 14:01 cleardesk

cleardesk:
-rw-r--r-- 1 root www-data 13609 Nov 16 14:01 cleardesk.php
-rw-r--r-- 1 root www-data  3543 Nov 16 14:01 config.php
-rw-r--r-- 1 root www-data 17984 Nov 16 14:01 LICENSE
-rw-r--r-- 1 root www-data   865 Nov 16 14:01 plugin.php
-rw-r--r-- 1 root www-data  5361 Nov 16 14:01 README.md

    Check that plugin.php, config.php and cleardesk.php are all listed.

  5. Make sure the web server can read the files. In the listing above, each line starts with the permissions, then the owner (root) and the group (www-data). The web server usually runs as www-data. The files are fine if the third r from the left is present (-rw-r--r--), which means everyone may read them, or if the group is the web server's and the group may read.

    If the files are not readable by the web server, or you want the owner to match your other osTicket files, set the owner and group to the same as those files. For example:

    sudo chown -R www-data:www-data cleardesk

Part 2: switch it on in the admin panel

These steps and the wording on screen are from osTicket 1.18. Two separate switches matter: the plugin's Status must be Active, and its instance's Status must be Enabled. If either is off, nothing is sent.

  1. In a web browser, sign in to your helpdesk's agent panel (the /scp address, for example https://support.example.com/scp) with an administrator account.

  2. Click Admin Panel, near the top right of the page.

  3. Click the Manage tab, then Plugins.

    You should see a page titled "Installed Plugins".

  4. Click Add New Plugin.

    You should see a page titled "Install a new plugin". It lists Clear Desk notifications with an Install button beside it. If it is not listed, stop here and see The plugin is not listed under Troubleshooting.

  5. Click Install beside Clear Desk notifications.

    You should see a green bar saying "Successfully installed a plugin". The page heading reads "Plugins > Clear Desk notifications ( Disabled )". Below it there are two tabs: Plugin and Instances (0).

  6. On the Plugin tab, set Status to Active.

  7. Click Save Changes.

    You should see a bar saying "Plugin Updated Successfully". The heading now ends "( Active )".

  8. Click the Instances tab.

  9. Click Add New Instance.

    You should see the Add New Instance form. It has two tabs: Instance and Config.

  10. On the Instance tab:

    • In Name, type a name, for example Clear Desk. The name is only for you.
    • Set Status to Enabled.

  11. Click the Config tab.

    • Leave Delivery service address as it is. Do not change it.
    • Under "Tell agents about" there are four lists, each set to On or Off. They decide which kinds of event the helpdesk sends at all. The suggested settings are:
      • New tickets: On
      • Customer replies: On
      • Assignments: On
      • Internal notes: Off
    • A kind you set to Off here is never sent to anyone, whatever agents choose in the app. Agents see it greyed out.

  12. Click Add Instance.

    You should see a bar saying "Plugin Added Successfully". The Instances tab now shows one instance.

  13. Check both switches once more: the heading should end "( Active )", and the instance should be Enabled.

The administrator's part is done. Nothing is sent until at least one agent switches notifications on in the app.

The first time an agent's device registers, the plugin creates one database table, ost_cleardesk_device. If your helpdesk uses a different table prefix than ost_, the table has your prefix instead. The plugin makes no other changes to the database.

Part 3: each agent switches it on in the app

Each agent who wants notifications does this once on each iPhone or iPad. They need Clear Desk version 1.1 or later, signed in to your helpdesk.

  1. Open Clear Desk and go to the Queues screen.

  2. Tap the gear button to open Settings.

  3. Find the Notifications section.

    If it says "Needs the free Clear Desk plugin on your helpdesk. Ask your administrator.", the app cannot find the plugin. See The app says the plugin is needed under Troubleshooting.

  4. Switch on Instant notifications.

    On the free plan, this opens the subscription screen instead. Notifications need Clear Desk Full.

  5. When iOS asks whether Clear Desk may send notifications, tap Allow.

  6. Four switches now appear:

    • New tickets (starts on)
    • Customer replies (starts on)
    • Assigned to me (starts on)
    • Notes from colleagues (starts off)

    Turn each on or off as you prefer. A kind the administrator has turned off in the plugin is greyed out and marked "Switched off by your administrator".

Part 4: test it

You are never told about something you did yourself, so the test needs a ticket from someone else.

  1. Make sure at least one agent has finished Part 3, and keep that agent's phone to hand. It can be locked.

  2. Have someone who is not signed in as an agent open a new ticket: send an email to the helpdesk's address, or use the helpdesk's web form for customers. You can do this yourself from a private browser window or a personal email address.

  3. Within a few seconds the phone should show a notification: "Ticket #…" with the text "New ticket".

    If the ticket went into a department the agent cannot see, or was assigned straight to someone else, that agent is not told. See Who gets told.

  4. Tap the notification. Clear Desk should open that ticket.

  5. Reply to the ticket as the customer: reply to the email the helpdesk sent, or add a reply through the customer web page.

    The phone should show "Ticket #…" with the text "The customer replied".

If nothing arrives, see The switch is on but nothing arrives.

Who gets told

  • If the ticket is assigned to an agent, that agent is told.
  • If it is assigned to a team and not to a person, the members of that team are told.
  • If nobody is assigned, every agent with access to the ticket's department is told.
  • Only agents who have switched notifications on in the app, and only for the kinds they have chosen, are told.
  • Agents marked as on vacation in osTicket are skipped.
  • Agents whose access is limited to their own assigned tickets are not told about unassigned tickets.
  • You are never told about something you did yourself.
  • Assignments tells the new assignee when someone else assigns a ticket to them. Claiming a ticket yourself does not send one.

What is sent, and where

For each event, the plugin sends the delivery service only:

  • the kind of event: new, reply, assigned or note;
  • the ticket's number and its internal id;
  • the device tokens of the agents to tell. A device token is the address Apple uses to deliver a notification to one app on one device.

A complete example, with the token shortened:

{"v":1,"event":"reply","ticket":{"id":123,"number":"374502"},"devices":[{"token":"…","env":"production"}]}

It never sends the subject, any message text, the customer's name or email address, any agent's name, or your helpdesk's address.

The delivery service is a small service run by Clear Desk's developer, hosted on AWS in Ireland. It passes the notification to Apple. It is needed because Apple only accepts notifications for an app from that app's publisher. The delivery service keeps no record of the requests it receives.

What can still be worked out: the delivery service and Apple can tell that a server at a certain IP address had an event on a ticket with a certain number at a certain time.

On your server, the plugin stores, for each registered device: the agent's id, the device token, and the kinds of notification that agent has chosen. It is kept in the table ost_cleardesk_device (with your table prefix).

If the delivery service is slow or cannot be reached, the plugin gives up after a few seconds (2 seconds to connect, 4 seconds in total) and the ticket is saved as normal. A warning titled "Clear Desk notifications" is written to osTicket's system log, which you can read under Admin Panel, Dashboard, System Logs.

The app's privacy policy covers this too.

Troubleshooting

The plugin is not listed under Add New Plugin

osTicket did not find the plugin's files. Check each of these:

  • The folder is at include/plugins/cleardesk inside osTicket's folder, and not somewhere else.
  • The folder is named exactly cleardesk. A folder still called ClearDeskPlugin-main is not found.
  • There is no folder inside a folder. include/plugins/cleardesk/plugin.php must exist, not include/plugins/cleardesk/ClearDeskPlugin-main/plugin.php.
  • plugin.php and config.php are both present (and cleardesk.php, which is needed later).
  • The files can be read by the user the web server runs as.

After fixing it, reload the "Install a new plugin" page.

The app says the plugin is needed

The Notifications section says "Needs the free Clear Desk plugin on your helpdesk. Ask your administrator." Check:

  • In the admin panel, the plugin's Status is Active. The heading on the plugin's page should end "( Active )".
  • On the plugin's Instances tab, there is an instance and its Status is Enabled.
  • If both are right, the agent should close Settings in the app and open it again.

The switch is on but nothing arrives

Work through these in order:

  • Notifications for Clear Desk are allowed in the iPhone's own Settings app: Settings, Notifications, Clear Desk.
  • No Focus mode (such as Do Not Disturb or Work) is holding the notifications back.
  • The agent did not do the action themselves. You are never told about your own actions.
  • The ticket is not assigned to someone else. Only the assignee, or the assigned team, is told about an assigned ticket.
  • The agent is not marked as on vacation in osTicket, and has access to the ticket's department.
  • That kind of event is On in the plugin's Config tab, and switched on in the app.
  • The server can reach the delivery service. Look in Admin Panel, Dashboard, System Logs for warnings titled "Clear Desk notifications", and run the curl check from Before you start again.

Notifications stopped after reinstalling the app

Reinstalling gives the app a new device token. In Clear Desk, open Settings, switch Instant notifications off, then on again.

Updating, turning off and removing

Updating the plugin

  1. Download the new version as in Part 1.

  2. Replace the three files plugin.php, config.php and cleardesk.php in include/plugins/cleardesk with the new ones. If you installed with git, you can instead run git pull inside that folder.

The plugin's settings and the registered devices are kept.

Turning it off for a while

  1. Go to Admin Panel, Manage, Plugins, and click Clear Desk notifications.

  2. On the Plugin tab, set Status to Disabled and click Save Changes.

Nothing is sent while it is disabled. Set it back to Active to start again.

Removing it completely

  1. Go to Admin Panel, Manage, Plugins. The page is titled "Installed Plugins".

  2. Tick the box beside Clear Desk notifications.

  3. Click More, then Delete, and confirm.

  4. On the server, delete the folder include/plugins/cleardesk.

  5. Optionally, delete the plugin's table from the database. With the default prefix the command is:

    DROP TABLE ost_cleardesk_device;

    If your helpdesk uses a different table prefix, use that instead of ost_.
